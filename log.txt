STEP 2.1 — CLEAN QUERY FLOW EXPERIMENT

Mục tiêu:
Loại bỏ các logic đã được chứng minh gây hại:
- hardcoded traffic intent routing
- Forced Target Article Injection
- rule-based Query Decomposition hiện tại

CHƯA đổi RRF weight.
CHƯA bật Reranker.
CHƯA đổi embedding.
CHƯA sửa benchmark.
CHƯA sửa production.

==================================================
1. QUERY FLOW
==================================================

Production experiment flow:

Original user query
        ↓
Dense Retrieval
        +
Sparse Retrieval
        ↓
RRF
        ↓
Final Top-K

Không tạo subquery trong experiment này.

Không ép:
- tốc độ → NĐ168
- nồng độ cồn → điều xử phạt
- làn đường → tài liệu cố định
- bất kỳ article number hardcoded nào

==================================================
2. FEATURE FLAG
==================================================

Không xóa hoàn toàn Query Decomposition code.

Thêm feature flag:

ENABLE_QUERY_DECOMPOSITION=false

Default = false.

Giữ code cũ để phục vụ future experiment.

==================================================
3. FORCED TARGET ARTICLE
==================================================

Tắt cơ chế Forced Target Article Injection trong default flow.

Không xóa implementation nếu chưa cần.

4. RRF WEIGHTS
==================================================

GIỮ NGUYÊN cấu hình vừa được chọn:

dense_weight = 1.0
sparse_weight = 0.1

Không thử thêm weight trong bước này.

==================================================
5. EVALUATION
==================================================

Chạy toàn bộ Gold V2 225 cases.

So sánh với:

Dense-only:
Hit@1 = 38.22%
Hit@3 = 51.11%
Hit@5 = 54.67%

Previous Hybrid 0.10:
Hit@1 = 32.44%
Hit@3 = 50.67%
Hit@5 = 58.67%

Tính:
- Hit@1
- Hit@3
- Hit@5
- Miss@5

Ngoài ra:

- Dense PASS → Clean Hybrid PASS
- Dense PASS → Clean Hybrid FAIL
- Dense FAIL → Clean Hybrid PASS
- Dense FAIL → Clean Hybrid FAIL

Đặc biệt liệt kê:
- các case được cứu
- các case bị regression
- các case trước đây bị decomposition làm sai

==================================================
6. REGRESSION
==================================================

Chạy 25 frozen regression cases.

Không sửa cases.

Acceptance:
- Hit@1 >= 92%
- Hit@2 = 100%
- Hit@3 = 100%

==================================================
7. KHÔNG DÙNG NGƯỠNG 65–70%
==================================================

Không coi 65–70% là acceptance requirement.

Mục tiêu thực tế:
- Clean Hybrid không làm tệ hơn Dense baseline ở mức quan trọng.
- Nếu Hit@5 cải thiện rõ ràng so với Dense-only thì PASS.
- Nếu chỉ ngang Dense nhưng ổn định thì đánh giá là "marginal benefit" và có thể cân nhắc bỏ Hybrid complexity.
