1. Quyết định lớn: em nghiêng về Cloud Run trước

Trong hai lựa chọn backend, với mục tiêu của anh là $0 hoặc gần $0 để public beta, em chọn:

Google Cloud Run làm phương án chính của Phase 3.

Lý do là Cloud Run hiện hỗ trợ container, scale-to-zero và request-based billing. Free tier hiện là 2 triệu requests + 360.000 GiB-seconds RAM + 180.000 vCPU-seconds/tháng.

Quan trọng hơn, Cloud Run cho phép cấu hình 1 vCPU tối đa 4 GiB RAM, hoặc 2 vCPU tối đa 8 GiB, nên backend chứa BGE-M3 của anh có thể bắt đầu ở 1 vCPU/4 GiB hoặc 2 vCPU/4–8 GiB tùy benchmark.

Với 4 GiB RAM, riêng free-tier memory tương đương:

360,000 GiB-sec / 4 GiB
= 90,000 sec
≈ 25 giờ/tháng

Nên phép tính của agent là đúng.

Nhưng cần hiểu:

$0 không có nghĩa là Cloud Run được đảm bảo miễn phí vô điều kiện.

Free tier được áp dụng sau khi billing được thiết lập và còn phụ thuộc eligibility/khu vực/chính sách Google. Vì vậy mình phải theo dõi billing ngay từ đầu. Cloud Run cũng tính phí khi request đang xử lý, nên SSE dài sẽ tiêu tốn thời gian tính phí giống request bình thường.

2. Có một điểm em muốn sửa trong bảng CPU/RAM

Agent ghi:

Backend FastAPI + BGE-M3: tối thiểu 3 GB RAM.

Em không muốn dùng 3 GB làm production limit.

Vì 3 GB là mức sát nguy hiểm. Cloud Run nói memory limit bao gồm process, model, file system, cache và memory theo request/concurrency. Nếu vượt limit, instance bị terminate.

Cho nên ban đầu em sẽ để:

Cloud Run
CPU:    2 vCPU
RAM:    4–8 GiB
Min:    0
Max:    1
Concurrency: thấp

Sau đó benchmark memory thực tế.

Đặc biệt Cloud Run có lưu ý rằng concurrency cao sẽ làm tăng memory theo công thức:

standing memory + memory/request × concurrency.

Với RAG + embedding model lớn, đừng mặc định concurrency 80.

4. Qdrant Cloud: phần này em đồng ý

Thông tin hiện tại của Qdrant đúng:

0.5 vCPU
1 GB RAM
4 GB disk
single-node free cluster.

Qdrant cũng mô tả free tier có thể phục vụ khoảng 1 triệu vector 768 chiều trong điều kiện của họ, nên corpus hiện tại của anh với 7.093 vector chưa phải vấn đề.

Nhưng có một nuance rất quan trọng:

Free cluster sẽ suspend sau 1 tuần không hoạt động và bị xoá sau 4 tuần nếu không kích hoạt lại.

Vì vậy khi public beta, mình phải có ít nhất một monitoring/keep-alive strategy hợp lý hoặc chấp nhận việc free cluster có thể ngủ/xóa theo policy.

5. Phương án VPS vẫn phải giữ

Anh nên giữ:

Primary:
Google Cloud Run

Fallback:
4–8GB VPS

Vì nếu Cloud Run gây ra vấn đề như:

cold start quá lâu
memory pressure
SSE behavior
billing khó kiểm soát

thì Phase 2 đã chứng minh Docker Compose của anh chạy được.

Đó là ưu thế rất lớn:

Cloud Run fail
      ↓
VPS
      ↓
docker compose up -d

Không cần viết lại application architecture.
